# 📦 SBG-Warehouse RTVB2S

ระบบ Warehouse สำหรับสแกน Carton และสแกน SBC แบบ Realtime ใช้งานผ่าน PDA / Android / Desktop
ออกแบบมาสำหรับทีมงาน 5 คน ไม่มีระบบ Login ที่ซับซ้อน — เลือกชื่อแล้วใช้งานได้ทันที

## ✨ คุณสมบัติ

- HTML5 + CSS3 + Vanilla JavaScript — ไม่ใช้ Framework, ไม่ต้อง build
- เปิดไฟล์ `index.html` ใช้งานได้ทันที (double-click ก็เปิดได้)
- 3 โหมดการทำงาน: **Mockup**, **Setup**, **Real** (ดูรายละเอียดด้านล่าง)
- Realtime Dashboard ด้วย Firestore `onSnapshot`
- **Mobile-first** ออกแบบเน้นมือถือเป็นหลัก (90% ผู้ใช้งานผ่านมือถือ) รองรับ PDA / Android / Desktop
- รองรับทั้ง **USB Barcode Scanner** (ส่ง Enter หลังสแกน) และ **กล้องมือถือ** — กดปุ่ม 📷 ข้างช่องสแกนเพื่อเปิด/ปิดกล้อง Auto สแกน QR Code / Barcode ต่อเนื่อง
- **ระบบ Report 2 โหมด**: Summary (รวมยอดตาม Barcode พร้อมดูว่าอยู่ Carton ไหนบ้าง) และ Details (รายละเอียดแยกตาม Carton) พร้อมช่องค้นหา/กรองข้อมูล
- แถบชื่องานปัจจุบัน (Job Banner) ตัวใหญ่ เห็นชัดตลอดการใช้งาน
- โหมดธีม **มืด / สว่าง** สลับได้ (จำค่าไว้อัตโนมัติ)
- **Bottom Tab Bar** (footer nav) แบบมือถือ ไอคอน+ป้ายกำกับ ไฮไลต์ปุ่มที่กำลังใช้งานอยู่ชัดเจน
- **นำเข้าข้อมูลสินค้าจาก Excel (.xlsx)** — กำหนดคอลัมน์/แถวของ Barcode, ชื่อสินค้า, SKU แล้วดึงชื่อ/SKU มาแสดงอัตโนมัติเวลาสแกน (คล้าย XLOOKUP) — ซิงค์ขึ้น Firebase ให้ทุกคนใช้ข้อมูลชุดเดียวกันได้
- **ใช้งานพร้อมกันได้ทั้ง 5 คนแบบ Realtime** พร้อมแสดงสถานะว่าใครออนไลน์อยู่ในชื่องานเดียวกันบ้าง (Presence)
- **รายงานผลงานรายคน (Performance)**, **Undo ปิดชื่องาน** ได้ภายใน 5 นาที, **Audit Log** ประวัติการทำงานทั้งหมด
- **โหมดตรวจนับสต๊อก (Stock Take)** เทียบยอดสแกนจริงกับจำนวนที่ควรมี, **การแจ้งเตือน** เมื่อมีคนปิดงาน/สแกน Carton ใหม่
- **สลับภาษาไทย/อังกฤษ** สำหรับ UI หลัก
- **Push Notification แบบเต็มรูปแบบ** ผ่าน Backend แยก (Render) + Firebase Cloud Messaging — ได้รับแจ้งเตือนแม้ปิดแอป
- **PIN ป้องกันหน้าตั้งค่า** ตรวจสอบผ่าน Backend (ไม่ฝัง PIN ไว้ใน Frontend)
- **บล็อกสแกน Barcode ที่ไม่มีในฐานข้อมูลสินค้า** ป้องกันสแกนผิด/ของไม่มีอยู่จริง
- โลโก้ Siam Board Games, Footer Nav ตรึงล่างสุดบนมือถือพร้อมเรียงลำดับใหม่
- แก้ไข/ลบรายการที่สแกนผิดได้ก่อนบันทึก Carton, Export รายงานเป็น Excel, ค้นหาข้ามทุกชื่องานย้อนหลัง
- สำรอง/กู้คืนการตั้งค่าทั้งหมดเป็นไฟล์ JSON, เสียงแจ้งเตือนตอนสแกน, รองรับติดตั้งเป็นแอป (PWA)
- Toast Notification, Auto Focus input ทุกหน้า

## 🔄 Flow การใช้งาน

1. เลือกชื่อผู้ใช้ (1 ใน 5 คน) — ไม่ต้องใส่รหัสผ่าน
2. เลือกหรือสร้าง **"ชื่องาน"** ก่อน (เช่น "เช้า 18/07", "บ่าย 18/07", "ดึก 18/07")
3. สแกนเลข **Carton** → เริ่ม Session ใหม่
4. สแกน **SBC** ทีละชิ้น — เลือกโหมด **Scan Only** หรือ **Scan + Qty**
5. กดบันทึก → ระบบเขียนข้อมูลลง Firestore แบบ Batch Write
6. ดู Dashboard แบบ Realtime, ปิดชื่องานได้เมื่อทำงานเสร็จ (หลังปิดจะสแกนเพิ่มไม่ได้)

## 🧩 3 โหมดการทำงาน

### 1. MOCKUP MODE (ค่าเริ่มต้น)
ถ้ายังไม่ได้ตั้งค่า Firebase ระบบจะใช้ **Mock Database ใน Memory** โดยอัตโนมัติ
มีข้อมูลตัวอย่าง (Demo) ให้ทดสอบ UI ได้ทันที ข้อมูลจะหายเมื่อรีเฟรชหน้า
เหมาะสำหรับ: ทดสอบ UI/UX, Demo, พัฒนาโดยยังไม่มี Firebase Project

### 2. SETUP MODE
กดปุ่ม ⚙️ มุมขวาบน เพื่อกรอกค่า Firebase Config ผ่านหน้าเว็บโดยตรง
ค่าจะถูกเก็บใน `localStorage` (เข้ารหัส base64) — เหมาะกรณีไม่สะดวกใช้ Node.js

### 3. REAL MODE
เชื่อมต่อ Firebase จริง ผ่านไฟล์ `.env` (วิธีแนะนำ ปลอดภัยกว่า)

## ⚙️ วิธีตั้งค่า Firebase (REAL MODE) — แนะนำผ่าน .env

1. สร้างโปรเจกต์ Firebase ใหม่ที่ [console.firebase.google.com](https://console.firebase.google.com)
   เปิดใช้งาน **Firestore Database** (โหมด production หรือ test ก็ได้)
2. คัดลอกไฟล์ `.env.example` เป็น `.env`
   ```bash
   cp .env.example .env
   ```
3. เปิด `.env` แล้วใส่ค่าที่ได้จาก Firebase Console → Project Settings → General → Your apps → SDK setup and configuration
4. รันสคริปต์เพื่อ generate `js/env.js`:
   ```bash
   node scripts/build-env.js
   ```
5. เปิด `index.html` ใหม่ — ระบบจะขึ้น badge `REAL` มุมซ้ายบน แปลว่าเชื่อมต่อสำเร็จ

> ⚠️ **ห้าม commit ไฟล์ `.env` และ `js/env.js` ขึ้น Git** — ทั้งสองไฟล์ถูกใส่ไว้ใน `.gitignore` แล้ว
> ห้าม hardcode API Key ลงในโค้ดโดยตรงเด็ดขาด

### ทางเลือก: ตั้งค่าผ่านหน้าเว็บ (ไม่ใช้ Node.js)

ถ้าเครื่องไม่มี Node.js ก็สามารถกดปุ่ม ⚙️ ในแอป แล้วกรอกค่า Firebase Config ผ่านฟอร์มได้เลย
ค่าจะถูกเก็บไว้ใน `localStorage` ของเบราว์เซอร์นั้นๆ (ต้องตั้งค่าใหม่ทุกเครื่อง/ทุกเบราว์เซอร์)

## 🔐 Firestore Security Rules (ตัวอย่าง แนะนำให้ปรับใช้จริง)

เนื่องจากใช้ในองค์กร 5 คนและไม่มีระบบ Login ที่ซับซ้อน แนะนำให้อย่างน้อยจำกัด IP หรือใช้ Firebase App Check
ตัวอย่าง rule เบื้องต้น (เปิดอ่าน/เขียนแบบมีเงื่อนไขพื้นฐาน):

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /{document=**} {
      allow read, write: if true; // ⚠️ ปรับตามความเหมาะสม เช่นจำกัดด้วย App Check
    }
  }
}
```

## 📷 การสแกน — USB Scanner หรือ กล้องมือถือ

**USB Barcode Scanner:** เครื่องสแกนส่วนใหญ่จะพิมพ์ตัวอักษรแล้วตามด้วยปุ่ม **Enter** โดยอัตโนมัติ
ระบบดักจับ `Enter` ที่ input สแกนทุกช่อง (Carton, SBC) และประมวลผลทันที ไม่ต้องกดปุ่มเพิ่ม

**กล้องมือถือ:** กดปุ่ม 📷 ข้างช่อง input เพื่อเปิดกล้อง ระบบจะสแกน Barcode/QR Code ต่อเนื่องอัตโนมัติ
(ใช้ไลบรารี `html5-qrcode` โหลดผ่าน CDN — ต้องมีอินเทอร์เน็ตตอนโหลดหน้าเว็บครั้งแรก และเบราว์เซอร์ต้องได้รับอนุญาตสิทธิ์กล้อง)
กดปุ่ม 📷 อีกครั้งเพื่อปิดกล้อง เปิดได้ทีละกล้องเท่านั้น

## 📑 ระบบ Report

เข้าถึงได้จากปุ่ม "📑 รายงาน" ที่แถบเมนูด้านล่าง มี 2 โหมด:

- **Summary** — รวมยอดตาม Barcode/ชื่อเดียวกันทั้งงาน แสดงจำนวนชิ้นรวมและจำนวน Carton ที่พบ
  แตะแถวเพื่อขยายดูว่าอยู่ Carton ไหนบ้าง (พร้อมจำนวนต่อ Carton)
- **Details** — แสดงรายละเอียดแยกตาม Carton แต่ละใบมีอะไรบ้าง

ทั้งสองโหมดมีช่องค้นหาด้านบน กรองได้ทั้ง Barcode, ชื่อ SKU, และเลข Carton

## 📝 หมายเหตุ

- ไม่ต้องใช้ Node.js ในการรันแอปจริง — `node scripts/build-env.js` เป็นเพียงเครื่องมือช่วย generate config เท่านั้น
- ถ้าเปิดไฟล์ HTML ตรงๆ โดยยังไม่ได้ตั้งค่า Firebase ระบบจะเข้า **MOCKUP MODE** ให้อัตโนมัติ ไม่มี error

## 📇 นำเข้าข้อมูลสินค้าจาก Excel (Barcode Master)

กดปุ่ม 📇 มุมขวาบน เพื่อเข้าหน้าตั้งค่า:

1. เลือกไฟล์ `.xlsx` (อ่านเฉพาะชีทแรกของไฟล์)
2. กำหนดตำแหน่งข้อมูลทีละหัวข้อ — **คอลัมน์** (ตัวอักษรตามที่เห็นใน Excel เช่น A, B, C) และ **แถวเริ่มต้น** (แถวแรกที่มีข้อมูลจริง เช่นถ้าแถว 1 เป็นหัวตาราง ให้ใส่ 2):
   - Barcode = คอลัมน์ไหน | แถวไหน
   - ชื่อสินค้า = คอลัมน์ไหน | แถวไหน
   - SKU = คอลัมน์ไหน | แถวไหน
3. กด "นำเข้าข้อมูล (Import)" — ระบบจะอ่านทุกแถวตั้งแต่แถวเริ่มต้นจนจบไฟล์ แล้วสร้างเป็นตารางค้นหา (คล้าย `XLOOKUP`) เก็บไว้ใน `localStorage` ของเบราว์เซอร์นั้น

หลังนำเข้าแล้ว เวลาสแกน SBC ระบบจะค้นหา Barcode ที่สแกนในฐานข้อมูลนี้อัตโนมัติ ถ้าพบจะแสดงชื่อสินค้าและ SKU ต่อจาก Barcode ทันที ทั้งในหน้าสแกน และหน้า Report — ถ้าไม่พบจะยังสแกนบันทึกได้ตามปกติ เพียงไม่มีชื่อสินค้ากำกับ

> ⚠️ ข้อมูล Master ถูกเก็บแยกต่อเบราว์เซอร์/เครื่อง (ไม่ได้ sync ผ่าน Firebase) — ถ้าต้องการให้ทุกคนใช้ข้อมูลชุดเดียวกัน ให้แชร์ไฟล์ Excel แล้วให้แต่ละคนนำเข้าด้วยการตั้งค่าเดียวกัน

## 🧑‍🤝‍🧑 ใช้งานพร้อมกัน 5 คน + Presence Realtime

เมื่อเชื่อมต่อ Firebase จริง (REAL MODE) ระบบรองรับให้ทั้ง 5 คนใช้งานพร้อมกันได้ทันที ข้อมูลทุกอย่าง (Carton, สแกน SBC, ปิดชื่องาน ฯลฯ) จะ sync แบบ Realtime ผ่าน Firestore `onSnapshot` อยู่แล้วตั้งแต่แรก

เพิ่มเติม: หน้า **Dashboard** จะแสดงแถบ 🟢 **"กำลังใช้งานในงานนี้"** พร้อมอวาตาร์สีของแต่ละคนที่กำลังเปิดชื่องานเดียวกันอยู่ (กดค้างที่อวาตาร์เพื่อดูชื่อ) อัพเดททุก 15 วินาที และจะหายไปอัตโนมัติถ้าไม่มีการอัพเดทเกิน 40 วินาที (ปิดแอป/ออกจากงานนั้นแล้ว)

> หมายเหตุ: Presence ทำงานได้เต็มรูปแบบเฉพาะ REAL MODE เท่านั้น (ต้องมี Firebase) เพราะต้องอาศัยฐานข้อมูลกลางให้ทุกเครื่องเห็นร่วมกัน

## ☁️ ซิงค์ข้อมูล Barcode Master ขึ้น Firebase

เดิมข้อมูล Barcode Master (นำเข้าจาก Excel) จะถูกเก็บไว้ใน `localStorage` ของเบราว์เซอร์นั้นๆ เท่านั้น ตอนนี้ถ้าเชื่อมต่อ Firebase (REAL MODE) แล้ว:

- เมื่อกด **นำเข้าข้อมูล (Import)** ระบบจะซิงค์ข้อมูลขึ้น Firestore (`settings/barcodeMaster`) ให้อัตโนมัติ
- ทุกคนที่เปิดแอปด้วย Firebase config เดียวกัน จะได้รับข้อมูล Master ชุดล่าสุดแบบ Realtime ทันที โดยไม่ต้อง import เองทุกเครื่อง
- กด "ล้างข้อมูล Master" จะล้างทั้งบนเครื่องตัวเองและบน Firebase (ทุกคนจะเห็นว่างเปล่าเหมือนกัน)

> ⚠️ Firestore จำกัดขนาดต่อ 1 เอกสารไว้ที่ 1MB — ถ้ามีสินค้าจำนวนมากมาก (หลายหมื่นรายการ) อาจต้องแบ่งเก็บหลายเอกสารในอนาคต สำหรับการใช้งานทั่วไป (หลักพันรายการ) ไม่มีปัญหา

## ✏️ แก้ไข/ลบรายการสแกนก่อนบันทึก

## 🚀 สถาปัตยกรรมล่าสุด: Push Notification แบบเต็มรูปแบบ (ปิดแอปก็ยังได้รับ)

```
[มือถือ/PDA ของ 5 คน]
        │ เปิดเว็บแอป (Frontend — โฟลเดอร์นี้)
        ▼
[GitHub Private Repo] ──deploy──▶ [Render: Static Site (Frontend)]
        │
        └──deploy──▶ [Render: Web Service (backend/) + ENV Variables]
                              │
                              ├──▶ [Firebase Firestore] (ฐานข้อมูลหลัก — ใช้ตัวเดียวกับ Frontend)
                              │
                              └──▶ [Firebase Cloud Messaging] ──push──▶ มือถือ (แม้ปิดแอป/ปิดเบราว์เซอร์)
```

**หลักการทำงาน:**
- Frontend ยังคงอ่าน/เขียน Firestore ตรงเหมือนเดิมทุกจุด (ไม่มีอะไรเปลี่ยน)
- Backend (โฟลเดอร์ `backend/`) เป็นเซิร์ฟเวอร์แยกต่างหาก รันอยู่ตลอดเวลาบน Render คอย `onSnapshot` ฟัง Firestore เบื้องหลัง
- เมื่อมีคนปิดชื่องาน / เปิดชื่องานอีกครั้ง / สแกน Carton ใหม่ → Backend จะค้นหา FCM token ของคนอื่นๆ ในชื่องานเดียวกัน (จาก collection `fcmTokens`) แล้วยิง Push ผ่าน Firebase Cloud Messaging
- **ใช้งานได้แม้ผู้รับปิดแอป/ปิดเบราว์เซอร์ไปแล้ว** ต่างจาก local notification เดิมที่ต้องเปิดแอปทิ้งไว้เท่านั้น

**ดูรายละเอียดการ Deploy Backend ทั้งหมดที่ [`backend/README.md`](backend/README.md)** — รวมถึงข้อควรระวังสำคัญเรื่อง Render free tier ที่จะ sleep ถ้าไม่มีการ ping

## 🔔 วิธีเปิดใช้ Push Notification (ฝั่งผู้ใช้)

1. กด 🔔 เปิดการแจ้งเตือน ที่หน้า ⚙️ Setup เหมือนเดิม (ต้องอนุญาตสิทธิ์แจ้งเตือนของเบราว์เซอร์)
2. ถ้าตั้งค่า `FIREBASE_VAPID_KEY` และ deploy Backend ไว้ครบแล้ว ระบบจะขอ FCM Token อัตโนมัติ แล้วบันทึกไว้ที่ Firestore `fcmTokens/{userId}`
3. จากนั้นแม้ปิดแอปไปแล้ว ก็ยังได้รับแจ้งเตือนเมื่อมีคนปิดชื่องาน/สแกน Carton ใหม่ในชื่องานเดียวกัน
4. ถ้ายังไม่ได้ตั้งค่า VAPID Key หรือ Backend ระบบจะ fallback เป็น local notification แบบเดิม (ใช้ได้แค่ตอนเปิดแอปทิ้งไว้) โดยอัตโนมัติ ไม่มี error

## 🔒 PIN ป้องกันหน้าตั้งค่า (⚙️ Setup)

หน้า Setup (แก้ไข Firebase Config, Import/Export Backup) ตอนนี้ต้องใส่ **PIN** ก่อนเข้าใช้งาน:

- PIN ถูกเก็บไว้ที่ **ENV ของ Backend** (`ADMIN_PIN` บน Render) เท่านั้น — ไม่ได้ฝังอยู่ใน Frontend เลย ดังนั้นเปิด view-source ก็ไม่เจอ PIN
- ตรวจสอบผ่าน endpoint `POST /api/verify-pin` มี rate-limit กันสุ่ม PIN (ผิดเกิน 5 ครั้งใน 5 นาที ล็อกชั่วคราว)
- ใส่ PIN ถูกแล้วจะจำไว้แค่ในแท็บนั้น (sessionStorage) — ปิดแท็บ/รีเฟรชแล้วต้องใส่ใหม่
- **ถ้ายังไม่ได้ตั้งค่า `PUSH_BACKEND_URL`** ระบบจะข้าม PIN ไปอัตโนมัติ (กันตัวเองล็อกตายออกจาก Setup ตอนยังไม่ deploy backend)

> ⚠️ ข้อจำกัดที่ต้องเข้าใจ: นี่คือการป้องกัน "กันมือใหม่กดพลาด/กันคนไม่ตั้งใจ" ไม่ใช่ระบบความปลอดภัยระดับสูง เพราะ PIN ถูกส่งผ่าน HTTPS ไป Backend ตรวจสอบก็จริง แต่ตัวแอป Frontend เองยังเป็น Static Site ที่ทุกคนที่มีลิงก์เข้าถึงได้ ถ้าต้องการความปลอดภัยสูงกว่านี้ (เช่น ระบบ Login เต็มรูปแบบ) ต้องออกแบบเพิ่มเติม
